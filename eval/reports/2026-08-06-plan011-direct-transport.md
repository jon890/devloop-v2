# Plan011 — Responses 직접 전송 교차 측정 리포트

`Responses` 직접 전송과 상주 `app-server` 전송을 같은 코드·그래프·평가 세트로 번갈아 측정했다.
직접 전송은 문자당 처리 속도가 빨랐지만 답변이 길어져, 실제 질의의 총지연은 상주 전송보다 나빴다.

## 실행 조건

- 평가 세트: `eval/suites/tc-ocr-api-gateway.json`
- 실행 순서: 직접 1회차 → 상주 1회차 → 직접 2회차 → 상주 2회차
- `--stage`: 순서대로 `plan011-direct-1`, `plan011-appserver-1`, `plan011-direct-2`, `plan011-appserver-2`
- 질의 모델 선언값: `gpt-5.6-terra`. `--query-model` 은 선언값이며 런타임 모델을 증명하지 않는다
- 측정 커밋: `5971f3c604f4aa7bb4e088503fe9f39dfd2c773b`
- API: `PORT=3011`, `node dist/main.js` 로 직접 기동
- 실제 측정: 각 회차 12문항·36 attempts, 네 회차 합계 144 attempts
- 오류: 네 회차 모두 0건
- `suiteHash`: 네 회차 모두 `e90f5130182154bb31a82830ab0fb53a310d68ab88ab4ece9d1cf220aeabc43e`

그래프는 노드 3,082개, 관계 13,002개였다.

## 방법론 — 두 전송을 번갈아 측정했다

전송별로 몰아서 재지 않고 직접과 상주를 번갈아 실행했다.
같은 A/B 탐침을 한쪽씩 몰아 실행했을 때 시간대 경쟁이 한쪽에만 실려 결론이 뒤집힌 경험이 있었기 때문이다.

이 결과는 앞선 plan 의 다른 시간대 지연값에 의존한 판정도 다시 볼 여지가 있음을 보여준다.
`kg-eval` 러너 자체에 교차 실행 기능을 넣는 일은 이 plan 범위 밖이며 별도 작업으로 남긴다.

## 판정 1 — 실제 질의의 총지연은 나빠졌다

- 직접 전송 평균 구간: 57.9\~70.0초
- 상주 전송 평균 구간: 51.9\~56.2초
- 직접 전송 중위 구간: 56.4\~65.8초
- 상주 전송 중위 구간: 50.2\~53.4초

평균과 중위 구간 모두 겹치지 않는다.
동시대 기준인 상주 전송과 비교하면 직접 전송의 실제 질의 총지연은 회귀했다.

Plan010 최종 평균 54.1\~59.5초와 직접 전송 57.9\~70.0초도 대조할 수 있다.
다만 plan010 수치는 다른 시간대에 측정했으므로 참고값일 뿐이며, 이번 판정의 기준은 번갈아 잰 상주 회차다.

## 판정 2 — 답변 길이가 늘었고 문자당 처리는 빨라졌다

직접 전송의 회차 평균 답변 길이는 1,493\~1,691자이고 상주 전송은 844\~961자다.
두 회차 평균을 다시 평균하면 직접 1,592자, 상주 903자로 직접 전송이 약 1.76배 길다.

| 전송 회차 | 평균 지연 ÷ 평균 답변 길이 |
| --- | ---: |
| 직접 1회차 | 41.4ms/자 |
| 직접 2회차 | 38.8ms/자 |
| 상주 1회차 | 61.6ms/자 |
| 상주 2회차 | 58.4ms/자 |

두 문자당 구간은 겹치지 않으며, 회차 평균끼리 비교하면 직접 전송이 약 34% 빠르다.
직접 전송이 상주 전송과 같은 분량을 썼다고 단순 비례하면 평균 지연은 약 36초로 추정된다.
그러나 호출마다 고정 비용이 있고 출력 길이와 지연이 선형이라는 근거가 없으므로 실제 같은 길이의 지연을 증명한 값은 아니다.

긴 답변이 근거를 더 인용한 것인지 군더더기인지는 판정하지 않았다.
답변을 줄이는 후속 plan 에서는 근거 인용이 함께 줄어들지 않는지 확인해야 한다.

## 추론 강도와 추출 캐시

질의 API 는 `high` 를 명시해 두 전송에 같은 `reasoning.effort` 를 실었다.
Phase 02 에서 기존 상주 전송이 실제로 적용한 강도는 응답과 로그로 확인할 수 없었다.
로컬 `~/.codex/config.toml` 에 `model_reasoning_effort = "high"` 가 있었지만, 이는 설정 파일 값이지 해당 과거 호출의 런타임 증명은 아니다.

파이프라인 추출은 추론 강도를 지정하지 않는다.
`gpt-5.5@default` 캐시 537건을 유지하기 위한 의도적인 예외이며, 명시하면 전부 캐시를 빗나가 재추출한다.
추출 프롬프트와 `EXTRACTION_PROMPT_VERSION` 은 바꾸지 않았고 캐시 파일 총수 754건도 유지했다.

## 채택 결론과 남은 일

기본 전송은 Responses 직접 호출로 유지한다.
전송 자체는 문자당 약 34% 빠르지만 답변이 약 1.76배 길어 현재 실제 총지연은 상주 전송보다 나쁘다.
다음 plan 에서 답변 분량 지시를 조정하고, 줄인 답변이 근거 인용을 잃지 않는지 함께 측정한다.

상주 `app-server` 전송은 내부 엔드포인트 변경이나 회귀에 대비한 되돌리기 경로로 남긴다.
