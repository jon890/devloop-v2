# OpenWiki와 Experience Memory 실측 비교 보고서

작성일은 2026년 8월 20일이다. 비교 대상은 OCR.API의 동일 커밋 `825aa2c7`이며, OpenWiki는 Claude 작업자가 Orca 조정 흐름에서 실행했다.

## 판정

**운영 비교는 완료했지만 생성 품질 비교는 미완료다.**

Experience Memory는 `gpt-5.6-luna`로 5개 근거 묶음을 추출해 30개 Memory를 만들고 네 질문을 검색했다. OpenWiki는 공식 `openai-chatgpt` 제공자와 로그인된 Codex 계정의 인증까지 성공했지만, 본 생성 호출이 계정 전체 사용량 한도 `429`로 중단돼 위키 파일을 만들지 못했다. 따라서 OpenWiki 답변의 정확성을 임의로 채점하지 않았다.

현재 근거로는 둘 중 하나를 고르는 구조가 아니다.

- OpenWiki는 현재 저장소의 구조와 코드를 폭넓게 설명하는 저장소 문서화 도구에 가깝다.
- Experience Memory는 Dooray 업무·댓글·위키와 여러 Git 저장소에서 변경 이유, 제약, 실패, 검증 결과를 출처 잠금 상태로 검색하는 이력 지식 경로다.
- 최종 방향은 Experience Memory를 코딩 에이전트의 과거 맥락 검색 기반으로 유지하고, OpenWiki는 한도 회복 후 현재 코드 설명 품질을 검증해 보조 계층으로 채택할지 결정하는 것이다.

## 실행 결과

| 지표 | Experience Memory | OpenWiki 0.3.3 |
| --- | --- | --- |
| 입력 원천 | Dooray 업무 490건, 댓글 854건, 위키 47건, Git 저장소 9개 | OCR.API 저장소 1개 |
| 정규화 결과 | 근거 묶음 2,739개, 구간 7,873개, 원천 참조 3,593개 | 저장소 복제 성공 |
| 생성 모델 | `gpt-5.6-luna` 고정 | `gpt-5.6-sol` 본 실행, `gpt-5.6-terra`·`gpt-5.4-mini` 진단 |
| 선택 입력 | 근거 묶음 5개 | 전체 저장소 초기화 시도 |
| 모델 호출 | 5회 성공, 0회 실패 | 인증 확인 성공 후 본 실행 `429` |
| 생성 시간 | 145,524밀리초 | 1초 후 중단 |
| 생성 결과 | Memory 문서 30개 29,733바이트, 색인 포함 파일 32개 144,149바이트 | 파일 0개, 0바이트 |
| 검색 | 문서 30개 검색, 질의당 1밀리초 | 생성물이 없어 측정 불가 |
| 원문 추적 | Memory마다 안정 식별자와 원문 링크 보존 | 생성물이 없어 측정 불가 |

Experience Memory 실행은 의도적으로 근거 묶음 5개만 추출했으므로 완전 색인이 아니다. 이 수치는 도구 간 전체 처리량 비교가 아니라, 같은 질문에 답할 수 있는 최소 실측이다.

## 네 질문에서 확인한 검색 품질

| 질문 | Experience Memory 실측 | 판정 |
| --- | --- | --- |
| 공개 경로 오류 계약 | 안정적인 오류 식별자와 진입 표식 헤더를 포함하면 정확한 결정이 1위로 검색됐다. | 핵심 근거 도달 |
| 진입 경로 구분과 관측 제거 | 한국어 질의만으로 Dooray의 전환 결정과 Git의 관측 제거 결정을 함께 찾았다. | 이력과 현재 계약을 함께 복구 |
| 업로드 크기 계약 | 붙여 쓴 단위 표기는 정답 Memory를 상위 5개에 올리지 못했다. 단위를 띄우고 추출 언어를 맞추면 2위로 검색됐다. | 검색어 민감도 존재 |
| 내부 요청 판정 | 전달 헤더 우선순위, 직접 주소 동시 검증, 허용 주소 범위, 잘못된 IP 처리, ASCII 검증이 상위 5개에 모였다. | 관련 제약 묶음 복구 |

검색 결과는 모두 30개 문서를 훑어 1밀리초에 반환됐다. 다만 Memory 제목 30개 중 23개가 영어로 생성돼, 한국어 어휘 검색의 재현율이 낮아졌다. Dooray 업무에서 추출한 제목은 한국어였지만 비교에 사용한 Git ADR 4건의 결과는 영어였다. 이는 검색 단계보다 추출 단계의 언어 일관성 문제다. 한국어 고정 출력과 식별자·숫자 토큰 정규화를 다음 개선 항목으로 본다. 축약 검색 결과는 비공개 실행 경로의 `answers/memory-search-results.json`에 보존했다.

## OpenWiki 실제 실행에서 발견한 점

### 공식 Codex 로그인을 사용할 수 있다

OpenWiki의 `openai-chatgpt` 제공자는 현재 Codex 로그인 정보를 프로세스 환경으로 전달하면 인증된다. 작은 확인 호출에서 `gpt-5.6-sol` 응답을 받았다. 자격 증명 값은 파일이나 로그에 기록하지 않았다.

### 계정 전체 사용량 한도가 생성을 막았다

본 실행은 `429 The usage limit has been reached`로 종료됐다. `gpt-5.6-terra`와 `gpt-5.4-mini`의 최소 진단 호출도 같은 결과였으므로 특정 모델 거부가 아니라 계정 경로 전체의 현재 한도다. 사용자는 비용보다 정확성을 우선했으므로, 한도 회복 후 재실행 모델은 `gpt-5.6-sol`로 유지한다. `gpt-5.6-luna`로 낮춰 결과를 만들지는 않는다.

### 심볼릭 링크를 처리하지 못한다

OCR.API의 `AGENTS.md`는 `CLAUDE.md`를 가리키는 심볼릭 링크다. OpenWiki가 두 경로에 관리 표식을 쓰면서 같은 파일에 종료 표식이 중복됐고 초기화가 중단됐다. 원본 저장소는 변경하지 않았으며, 재실행 때는 임시 복제본에서 `AGENTS.md`만 일반 파일로 바꿔야 한다.

## 구조 차이

| 관심사 | Experience Memory | OpenWiki |
| --- | --- | --- |
| 중심 질문 | 과거에 왜 이렇게 결정했고 어떤 제약과 실패가 있었는가 | 현재 저장소는 무엇이며 어떻게 동작하는가 |
| 원천 범위 | Dooray 업무·댓글·위키와 OCR Git 저장소 전체 | 실행한 Git 저장소 |
| 저장 단위 | 결정, 제약, 사건, 교훈 | 저장소 설명 문서 |
| 신뢰 장치 | 원천 종류·식별자·개정·직접 링크, 상태와 신뢰도 | 생성 문서가 가리키는 저장소 문맥 |
| 검색 경로 | 결정적 어휘 검색, 필요할 때만 원문 확인 | 생성된 위키 문서를 에이전트가 탐색 |
| 실패 정책 | Luna를 사용할 수 없으면 명시 실패, 다른 모델로 승격하지 않음 | 선택 제공자의 한도와 저장소 형태에 영향 받음 |
| 강점 | 저장소 밖의 이유와 시간축, 원문 추적 | 현재 코드 구조의 폭넓은 설명 가능성 |
| 이번 실측의 약점 | 영어 추출로 인한 한국어 검색 민감도, 일부 Dooray 원천의 최신성 부족 | 계정 한도와 심볼릭 링크 때문에 생성 불가 |

## 원문 링크에 대한 결론

원문 링크는 필요하다. Memory는 정답 자체가 아니라 코딩 에이전트가 작업 전에 읽을 압축된 근거다. 상태가 `uncertain`이거나 원천이 충돌하면 에이전트가 원문으로 이동해 현재 코드를 다시 확인할 수 있어야 한다.

다음 네 값을 함께 보존하는 현재 계약을 유지한다.

1. 원천 종류
2. 안정적인 원천 식별자
3. Git 개정 또는 원천 발생 시각
4. 접근 권한이 있는 사용자가 열 수 있는 직접 링크

공개 보고서에는 사내 URL을 노출하지 않고, 실제 비공개 Memory 문서에서만 링크를 제공한다. 원문을 복제해 저장하지 않는 원칙도 유지한다.

## 현재 한계

- 이번 Dooray 원본 스냅샷에는 비교 대상으로 검토한 일부 최신 업무가 없었다. Dooray 최신 수집 뒤 같은 추출을 다시 수행해야 한다.
- `~/projects/OCR`에는 같은 저장소의 연결 작업 트리가 있어, 원본 루트를 직접 정규화하면 중복 저장소 식별자 검증이 실패했다. 비교 실행은 읽기 전용 복제본 9개로 격리했다.
- OpenWiki 생성물이 없으므로 정확성, 인용 충실도, 생성 시간, 문서 크기의 정면 품질 비교는 아직 할 수 없다.
- OpenWiki 0.3.3의 `openai-chatgpt` 경로는 호출별 토큰 수와 비용을 출력하지 않아 비용 비교도 할 수 없다.

## 재실행 완료 조건

다음 조건을 모두 만족할 때 비교를 완료로 바꾼다.

1. 로그인된 Codex 계정으로 `gpt-5.6-sol` 최소 호출이 성공한다.
2. 임시 복제본의 `AGENTS.md` 심볼릭 링크를 일반 파일로 격리한다.
3. OpenWiki가 파일을 한 개 이상 생성하고 정상 종료한다.
4. Claude 작업자가 생성된 위키만 사용해 네 질문에 답한다.
5. 코드·시험·ADR로 만든 정답지와 답변을 정확, 부분, 오류, 근거 없음으로 독립 판정한다.
6. 두 시스템의 생성 시간, 문서 수, 바이트, 검색 시간, 원문 추적성을 같은 표에 갱신한다.

## 최종 목표

최종 목표는 Dooray 업무·댓글·위키와 OCR Git 저장소 전체에서 **코딩 에이전트가 작업 전에 과거 결정, 호환성 제약, 장애 원인, 마이그레이션 맥락을 빠르게 찾고 원문까지 검증할 수 있는 지식 저장소**를 구축하는 것이다.

지식 추출과 LLM 기반 검색이 필요하면 우리 경로에서는 비용 상한을 위해 `gpt-5.6-luna`만 사용하고, 사용할 수 없으면 더 비싼 모델로 대체하지 않는다. 정규화와 어휘 검색은 결정적으로 유지한다. OpenWiki 비교 실행은 이 제품 규칙의 적용 대상이 아닌 외부 기준선이며, 정확성 우선으로 `gpt-5.6-sol`을 사용한다.

이번 결과는 OpenWiki가 불필요하다는 뜻이 아니다. 현재는 Experience Memory가 목표 범위를 직접 충족하고 있으며, OpenWiki는 한도 회복 후 “현재 코드 설명 계층”으로 보완 가치가 있는지 다시 측정해야 한다.
