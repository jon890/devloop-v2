## 기준선의 한계 — 1회 측정이었다

기존 기준선(`2026-07-27-axis-baseline.md`)은 34문항을 **1회씩** 측정한 값이다 (총 1,155초).
그 문서에 "아래 13문항이 FAIL 로 바뀌면 회귀다" 라고 적혀 있지만 **근거가 부족하다.**

실측으로 확인했다 — 기준선의 통과 13건 중 2건이 우연이었다.

| 문항 | 기준선 (1회) | main 3회 재측정 | 이 브랜치 3회 | 판정 |
| --- | --- | --- | --- | --- |
| A-08 | 통과 | **F/F/F** | F/F/F | 회귀 아님 |
| H-18 | 통과 | **F/F/F** | F/F/F | 회귀 아님 |

두 문항은 main 에서도 전회 실패한다. 기준선이 이 둘을 통과로 잡은 것은 1회 측정의 우연이었다.

- 총수 비교(13 대 13)만으로 "개선 없음" 이라 결론하지 마라
- 회귀가 의심되면 **그 문항만 main 에서 3회 측정**해 비교한다. 전체 기준선 재측정(102질의, 1시간)은 불필요하다

## 측정 방법

```bash
# API 기동
cd <워크트리> && PORT=<포트> pnpm api

# 34문항 x 3회
bash run-eval-anchor.sh <출력디렉터리> 3 <포트>

# 판정 (기준선과 같은 스크립트) — rep 별 디렉터리로 나눠 각각 실행
python3 score-baseline.py <rep별 디렉터리>
```

질문 파일은 `main` 기준(`eval/questions-*.json`)을 읽는다. `gold.required` / `gold.supporting` 구분이 여기에 있다.
`groundTruthCypher` 문항 7건은 `required` 가 없어 미판정으로 뺀다.
