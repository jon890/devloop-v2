## 해석 — 기준이 엄격한 게 아니라 엔진이 못 하고 있다

필수/보강 기준은 "답이 틀리는 항목만 무결점 요구" 이므로 관대한 편인데도 48%(13/27)만 통과한다.
그리고 실패 사유가 **판정 경계 문제가 아니라 명백한 실패**다 — 6문항은 엔진이 스스로 "근거에 없습니다" 라고 답했다.

즉 지금 필요한 것은 기준 완화가 아니라 앵커·경로 개선이다.

### GitHub 통합에 대한 함의 (중요)

앵커 후보 선정에서 **짧은 필드가 긴 필드를 밀어내는 현상이 이미 실재**한다 (H-04: Concept 이름이 Wiki 제목을 밀어냄).
계획이 추가하려는 `Deployment.app`(`api`·`admin` 같은 한 토큰)은 더 짧으므로 이 문제를 악화시킨다.

**따라서 GitHub 노드를 넣기 전에 앵커 선정을 먼저 고쳐야 한다.**
계획의 Phase 순서에서 질의 엔진 앵커 개선(현 Phase 9)을 GitHub 적재(현 Phase 8) 앞으로 올려야 한다.
