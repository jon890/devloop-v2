# 구현 완료 뒤 목표 상태 문구가 남았다

## 관찰

두 번째 누적 코드 검토에서 흐름과 아키텍처 문서가 판단 저장소를 아직 미구현이라고 설명하는 부분을 발견했다.

## 원인

스키마 절과 상단 기술 표만 현재 상태로 바꾸고, 같은 목표 상태를 설명하던 인접 문단을 함께 찾지 않았다.

## 영향

현재 실행 경로가 판단 저장소를 읽는다는 사실과 실제 패키지 경계를 문서 독자가 반대로 이해할 수 있다.

## 대응

흐름 문서에 판단 저장소를 읽는 네 단계와 읽지 않는 두 단계를 현재형으로 구분했다.
아키텍처 문서에는 `packages/registry`의 책임과 파이프라인 명령 진입점을 기록했다.

## 검증

`미구현`과 `아직 실행 경로에 없다` 문구가 판단 저장소 설명에 남지 않았는지 검색했다.
누적 코드 검토 재검사로 문서와 구현의 정합성을 다시 확인한다.

## 배운 점

목표 설계를 현재 상태로 전환할 때 같은 내용을 소유한 표와 본문을 함께 검색해야 한다.

## 후속

일반 규칙으로 승격하지 않는다.
누적 코드 검토와 문서 검증 단계가 같은 부패를 찾는 안전망을 소유한다.
