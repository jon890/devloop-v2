# 최상위 완료와 하위 상태 표기가 어긋났다

## 관찰

문서 검증에서 plan 색인은 완료됐지만 phase 본문 네 개와 PRD 항목이 미완료 상태로 남은 것을 발견했다.
아키텍처 문서에는 제거된 사전 로더와 누락된 트랜잭션 경계 절도 있었다.

## 원인

최상위 색인과 진행 표만 갱신하고 같은 상태를 나타내는 하위 문서 표기를 함께 찾지 않았다.

## 영향

후속 작업자가 완료된 계획을 미완료로 오인할 수 있고, 계층 경계의 설계 근거 위치를 찾을 수 없다.

## 대응

phase 본문 네 개와 PRD 항목을 완료 상태로 맞췄다.
아키텍처 문서에서 제거된 로더 설명을 현재 공용 로더로 바꾸고,
`packages/registry`의 repository와 service 트랜잭션 경계를 명시했다.

## 검증

phase 색인과 본문 상태가 모두 `completed`인지 확인했다.
코드에서 `readProjectConcepts`가 0건이고 repository의 트랜잭션 호출이 0건인지 검색했다.
문서 검증 재검사로 관리 문서 간 정합성을 다시 확인한다.

## 배운 점

완료 상태는 색인 하나가 아니라 phase 본문과 제품 진행표까지 함께 갱신해야 한다.
계획이 특정 문서 절을 계약 소유자로 가리키면 그 절의 존재도 검증해야 한다.

## 후속

일반 규칙으로 승격하지 않는다.
task 상태 검사와 문서 검증 단계가 재발 방지 근거를 소유한다.
