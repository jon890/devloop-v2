# 변이가 적용되지 않았는데 테스트가 통과해 무력한 테스트로 보였다

## 관찰

phase-04 에서 `outputSchema` 전달을 보호하는 테스트를 추가한 뒤 변이 검증을 했다.
`perl -0pi` 로 전달 코드 세 줄을 통째로 지우려 했는데 **치환이 먹지 않았다.**

그 상태로 테스트를 돌리니 15건 전부 통과했다.

이 결과는 두 가지로 읽힌다.

- (a) 변이가 적용됐는데 테스트가 못 잡았다 → 그 테스트는 무력하다
- (b) 변이가 적용되지 않았다 → 검증 자체가 성립하지 않았다

executor 가 `grep`·`sed` 로 소스를 직접 확인해 (b) 임을 판별했다.
두 번째 시도에서 한 줄을 주석으로 바꾸자 **15건 중 1건이 실패했다** — 새로 넣은 그 테스트다.

## 원인

변이 검증 절차가 "무력화한다 → 테스트를 돌린다 → 실패하는지 본다" 세 단계인데,
**첫 단계가 실제로 수행됐는지 확인하는 단계가 없다.**

여러 줄을 정규식으로 지우는 방식은 공백·줄바꿈 차이로 조용히 실패한다.
그리고 그 실패는 "테스트 통과" 라는 정상적으로 보이는 결과로 나타난다.

## 영향

실제 피해는 없었다. executor 가 소스를 확인해 판별했다.

**(a) 로 읽었다면 방금 추가한 테스트를 "무력하다" 고 판단해 지우거나 다시 쓸 뻔했다.**
그 테스트는 실제로 유효했고, 오히려 기존 14건이 이 전달을 전혀 보호하지 않고 있었다.

## 대응

변이 검증에 확인 단계를 하나 더 둔다.

1. 무력화한다
2. **소스가 실제로 바뀌었는지 확인한다** (`grep` 으로 해당 줄이 사라졌는지 본다)
3. 테스트를 돌린다
4. 실패하는지 본다
5. 원복하고 전건 통과를 재확인한다

여러 줄 정규식 치환보다 **한 줄을 주석으로 바꾸는 쪽이 확인하기 쉽다.**

## 검증

- 두 번째 변이(한 줄 주석화)에서 15건 중 1건이 실패했다
- 원복 후 15건 전부 통과했다
- 기존 14건은 변이 상태에서도 전부 통과했다 — 그 전달을 보호하지 않았다는 근거다

## 배운 점

`docs/pitfalls/testing.md` 는 "가드를 추가하면 변이로 검증하라" 를 기록했다.
**그 변이가 적용됐는지 확인하라는 항목은 없다.**

변이 검증은 실패를 기대하는 검증이라, 통과가 곧 이상 신호다.
그런데 "변이가 안 먹어서 통과" 와 "테스트가 무력해서 통과" 가 같은 모양으로 나타난다.
전자를 배제하지 않으면 유효한 테스트를 무력하다고 판단한다.

## 후속

`docs/pitfalls/testing.md` 의 "가드를 추가하면 변이로 검증하라" 절에
"변이가 적용됐는지 먼저 확인하라" 를 한 줄 더할지 검토한다.
