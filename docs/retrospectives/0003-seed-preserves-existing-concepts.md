# 사전 재생성이 기존 표기와 구조 전용 Concept 을 지웠다

## 관찰

실제 판단 5쌍을 적용한 뒤 `seed-concepts` 와 `resolve-graph` 를 연속 실행하자 두 문제가 드러났다.

- `OCR.Doc` 와 `OCR.DOC` 같은 표기가 정규화 키에서 충돌했다.
- 원천 시드에서 다시 발견되지 않은 `DocumentIdCardAuthenticityService:82`가 사전에서 사라져 해석이 실패했다.

## 원인

시더는 표준어를 정확한 문자열로만 합쳤다.
또한 기존 사전 항목 중 이번 원천 순회에서 다시 발견한 항목만 남겼다.

따라서 대소문자나 제어 문자만 다른 표기가 별도 표준어로 생길 수 있었다.
구조 파싱이 참조하지만 원천 시드 규칙이 직접 만들지 않는 기존 항목은 재생성 때 삭제됐다.

## 영향

정규화 충돌은 `resolve-graph` 를 중단시켰다.
구조 전용 항목 유실은 충돌을 고친 뒤 다음 해석에서 다시 실패를 일으켰다.
사람 판단이 사전 재생성을 견딘다는 Phase 03 핵심 조건을 실제 데이터에서 검증할 수 없었다.

## 대응

기존 사전에 정규화 키가 있으면 그 표준어를 우선한다.
기존 표준어가 없는 새 프로젝트에서는 코드포인트 순으로 승자를 정해 원천 순회 순서에 의존하지 않게 했다.

기존 사전 항목은 원천에서 다시 발견되지 않아도 보존한다.
사람이 흡수 대상으로 판단한 표준어는 이후 판단 합성에서 제거하므로 승인된 병합과 충돌하지 않는다.

## 검증

- 기존 표준어 우선, 신규 표준어의 결정적 승자, 구조 전용 항목 보존 회귀 테스트가 통과했다.
- 코드포인트 비교와 기존 항목 보존 가드를 각각 무력화했을 때 회귀 테스트가 실패했고 원복 뒤 통과했다.
- 실제 판단 5쌍으로 `seed-concepts` 를 다시 실행한 뒤 `resolve-graph` 산출물이 재생성 전과 바이트 단위로 같았다.
- 두 산출물의 SHA-256은 `ac86b2d97a30f99efbf60ec6fbe3b62d57a482cf4277758eabaaac5d59fdb10f`으로 같았다.

## 배운 점

재생성 안전성은 판단 행의 보존만으로 증명되지 않는다.
해석 단계가 소비하는 기존 사전 전체를 재생성 전후로 검증해야 한다.

## 후속

일반 규칙으로 승격하지 않는다.
시더 회귀 테스트와 실제 데이터 왕복 검증이 재발 방지 근거를 소유한다.
