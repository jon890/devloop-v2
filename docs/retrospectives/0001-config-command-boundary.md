# 전역 설정 이관이 명령 경계를 넓혔다

## 관찰

누적 코드 검토에서 두 결함을 발견했다.

- Neo4j를 쓰지 않는 명령까지 `NEO4J_URI`가 없으면 기동하지 못했다.
- `PIPELINE_DATA_DIR`를 메인 파이프라인에 확대 적용했지만 수집 단계에는 같은 경로를 넘기지 않아 `all` 실행의 쓰기·읽기 위치가 갈렸다.

## 원인

환경변수를 전역 설정 스키마로 모으면서 각 값의 기존 소비 명령 경계를 별도로 고정하지 않았다.
이관 대상이었던 `cli-options.ts`의 데이터 경로를 메인 파이프라인 전체에도 적용해 범위를 넓혔다.

## 영향

Phase 02에서 허용한 `NEO4J_URI` 필수화가 네 Neo4j 명령을 넘어 비DB 명령까지 번졌다.
또한 메인 파이프라인에서 새 데이터 경로를 사용하면 한 실행 안에서 단계별 대상 디렉터리가 달라질 수 있었다.

## 대응

Neo4j 설정 필수 가드를 실제 DB 진입점으로 좁힌다.
`PIPELINE_DATA_DIR`는 계획에 적힌 `sync-neo4j`와 `resolve-graph` 경로에만 적용한다.

## 검증

수정 전 상태다.
수정 후 비DB 명령의 설정 부재 회귀 테스트, 전체 단위 테스트, 빌드와 코드 검토 재검사를 기록한다.

## 배운 점

설정을 한 객체로 모으는 것과 모든 명령에 같은 필수 조건을 적용하는 것은 다른 결정이다.
동작 불변 이관에서는 환경변수마다 기존 소비 진입점을 테스트로 고정해야 한다.

## 후속

수정과 재검토가 끝나면 이 파일과 `INDEX.md`의 상태를 갱신한다.
