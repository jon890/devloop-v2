# 독립 코드 리뷰가 평가 계약 불일치를 드러냈다

## 관찰

두 차례 최종 독립 코드 리뷰에서 총 6건의 `NO-GO` 지적이 나왔다.
첫 3건은 `f3b3824`에서, 둘째 3건은 `2ec431a`에서 수정했다.

## 원인

평가 실행기와 보고서가 같은 값을 다루면서도 일부 계약을 서로 다르게 해석했다.
또한 중단 처리는 플래그만 세우고 진행 중인 입출력 자체를 끊지 않았다.
재시도와 조회 실패, versioned input 검증도 실행 중 상태와 영속 상태의 경계를 충분히 분리하지 않았다.

## 영향

원시 실행과 보고서의 해시 형태가 달라 같은 실행인지 기계적으로 대조하기 어려웠다.
축 변화와 경계 변화를 독립 사건으로 보지 않으면 비교 결과가 섞일 수 있었다.
중단 신호 뒤에도 진행 중인 요청이 계속되면 사용자가 중단했다고 믿은 뒤 추가 호출이 발생할 수 있었다.
재시도 파일에서 실패 회차가 남으면 완료 회차와 충돌할 수 있었다.
일시적 조회 실패를 캐시하면 그래프 상태가 없다는 durable 판단으로 굳을 수 있었다.
지원하지 않는 입력 버전을 받아들이면 이후 판정 계약이 조용히 어긋날 수 있었다.

## 대응

원시 실행과 보고서의 해시 형태가 같은 의미 계약을 공유하게 맞췄다.
축 변화와 경계 변화를 독립적으로 분류하게 했다.
신호 처리는 진행 중인 입출력을 실제로 중단하도록 고쳤다.
재시도 상태는 `questionId`와 `attempt` 쌍으로 식별하고 오류 회차를 대체하게 했다.
일시적 조회 실패는 durable graph state로 캐시하지 않게 했다.
versioned input은 지원하지 않는 버전을 거부하게 했다.

## 검증

`f3b3824`와 `2ec431a`에서 총 6건의 독립 리뷰 지적을 반영했고 후속 검증을 통과했다.

## 배운 점

원시 결과와 요약 결과는 같은 필드명을 쓰는 것보다 같은 의미 계약을 공유하는지가 더 중요하다.
경계 변화와 축 변화는 서로 다른 회귀 신호이므로 독립적으로 보존해야 한다.
중단 처리는 상태 플래그만으로 충분하지 않고 진행 중인 입출력을 끊어야 한다.
재시도 상태는 `questionId`와 `attempt`를 키로 삼고 오류 회차를 성공 회차로 대체해야 한다.
일시적 조회 실패는 durable graph state가 아니므로 캐시하면 안 된다.
버전이 있는 입력은 모르는 버전을 명시적으로 거부해야 한다.

## 후속

일반 규칙으로 승격하지 않는다.
독립 리뷰와 해당 회귀 검증이 재발 방지 근거를 소유한다.
