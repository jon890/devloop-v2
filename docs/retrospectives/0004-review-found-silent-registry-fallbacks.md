# 판단 조회 누락과 원천 소유권 충돌이 조용히 통과했다

## 관찰

누적 코드 검토에서 두 경로가 실패를 숨긴다는 지적을 받았다.

- 설정 객체가 없으면 판단 조회가 판단 0건으로 바뀌었다.
- 이미 다른 프로젝트에 연결된 원천을 등록해도 충돌 행을 확인하지 않고 성공 결과를 냈다.

## 원인

단위 테스트 편의를 위한 빈 판단 기본값이 운영 함수 경계까지 들어갔다.
원천 등록은 `on conflict do nothing`의 결과가 0건일 때 멱등 재실행과 다른 프로젝트 소유권 충돌을 구분하지 않았다.

## 영향

호출자가 설정 전달을 빠뜨리면 판단을 읽지 못한 실행이 정상 실행처럼 보인다.
원천 소유권 충돌은 프로젝트만 만들고 원천 연결은 만들지 않은 채 성공으로 보고될 수 있다.

## 대응

판단 조회 함수에서 설정 누락을 빈 판단으로 바꾸는 기본값을 제거했다.
테스트는 빈 판단을 명시적으로 주입해 운영 경계와 구분했다.

프로젝트 등록을 service 트랜잭션으로 감쌌다.
원천 삽입이 충돌하면 기존 원천의 프로젝트를 확인하고, 다른 프로젝트 소유면 실패해 프로젝트 생성까지 롤백한다.

## 검증

- 설정과 명시적 판단이 모두 없을 때 `seed-concepts`가 실패하는 회귀 테스트가 통과했다.
- 다른 프로젝트 소유 원천을 등록하면 실패하고 새 프로젝트도 남지 않는 Postgres 회귀 테스트가 통과했다.
- repository 파일의 트랜잭션 호출은 0건이고 service가 트랜잭션을 소유한다.

## 배운 점

멱등 등록과 소유권 충돌은 둘 다 `on conflict do nothing`에서 0건으로 보인다.
충돌 뒤 현재 소유자를 읽지 않으면 성공과 실패를 구분할 수 없다.

테스트 기본값은 운영 함수의 실패 의미를 바꾸지 않고 호출부에서 명시해야 한다.

## 후속

일반 규칙으로 승격하지 않는다.
service 트랜잭션과 회귀 테스트가 재발 방지 근거를 소유한다.
