# 관리 문서가 현재 구현과 목표 설계를 섞었다

## 관찰

문서 정합성 검증에서 두 종류의 부패를 발견했다.

- `docs/data-schema.md`가 Neo4j 명령의 제거된 기본값과 예전 필수 조건을 설명했다.
- `docs/code-architecture.md`와 `docs/flow.md`가 아직 없는 판단 저장소 패키지와 명령을 현재 구조처럼 적었다.

## 원인

Phase 02의 설정 동작 변경을 관련 관리 문서 전체에 반영하지 않았다.
또한 ADR 0005의 채택된 목표 설계를 현재 구현과 구분하지 않았다.

## 영향

문서대로 실행하면 `NEO4J_URI`가 없을 때 운영 기본값을 쓴다고 오해할 수 있었다.
저장소 구조를 탐색하는 사람은 존재하지 않는 패키지와 명령을 찾게 됐다.

## 대응

커밋 `b251c88`에서 네 Neo4j 명령이 대상을 명시해야 한다는 현재 규칙으로 설명을 고쳤다.
판단 저장소는 채택됐지만 미구현인 목표 설계라고 표시하고 현재 패키지·명령 목록에서 제외했다.

## 검증

두 차례 `UPDATE_NEEDED` 지적을 모두 반영한 뒤 문서 정합성 재검사 결과는 `PASS`였다.
현재 패키지 디렉터리, 파이프라인 스크립트와 네 Neo4j 가드 위치를 문서와 대조했다.

## 배운 점

채택된 ADR은 구현 완료를 뜻하지 않는다.
현재 구조를 소유하는 문서에서는 목표 설계를 명시적으로 구분해야 한다.

## 후속

일반 규칙으로 승격하지 않는다.
현재 상태와 목표 상태를 구분한 관리 문서가 이 저장소의 근거를 소유한다.
