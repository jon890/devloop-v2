# 함정 — 품질 측정

**측정을 돌리기 전에 읽는다.** 여기 적힌 것은 전부 이 저장소에서 실제로 겪었다.

## 1회 측정으로 개선·회귀를 판정하지 마라

같은 질문을 반복하면 판정이 달라진다. LLM 이 만드는 앵커 용어와 Cypher 가 실행마다 바뀐다.

| 측정 | 변동 폭 |
| --- | --- |
| `gpt-5.6-sol` · 정리 전 그래프 | 7문항 중 2문항 = 29% |
| `gpt-5.6-terra` · 정리 후 그래프 (2026-07-28) | 27문항 중 2문항 = 7.4% |
| plan006 — 코드·그래프 불변으로 두 번 측정 | attempt 36건 중 **8건 이동** (5건이 순수 변동) |

- **하지 말 것**: 한 번 재고 숫자가 좋아졌다고 개선이라 부르기
- **대신 할 것**: 같은 코드로 **두 번** 재서 구간을 만든다. 변경 전 구간과 겹치지 않을 때만 개선이라 부른다
- 변동 문항은 개선도 회귀도 아니라 **판정 불가**로 분류한다
- 변동이 줄어든 것을 특정 원인 덕이라고 단정하지 마라. 모델과 그래프가 함께 바뀐 측정은 원인을 가르지 못한다

실제 사례 — 재적재 후 "필수 통과 13 → 14" 를 얻었으나 반복 측정에서 개선 1건과 회귀 1건이 상쇄된 잡음이었다.

## A/B 전송을 한쪽씩 몰아 측정하지 마라

plan011 의 같은 A/B 단일 호출 탐침에서 한 전송을 몰아 잰 뒤 다른 전송을 몰아 재자 시간대 경쟁이
한쪽에만 실려 결론이 뒤집혔다. 실제 질의 측정은 직접 → 상주 → 직접 → 상주 순서로 교차했다.

- **하지 말 것**: A 를 모두 측정한 뒤 B 를 모두 측정하고 차이를 전송 효과라고 부르기
- **대신 할 것**: A1 → B1 → A2 → B2 처럼 번갈아 측정하고, 각 전송의 반복 구간이 겹치는지 판정한다
- 앞선 plan 의 다른 시간대 값은 참고로만 쓰고, 같은 시간대 교차 측정값을 현재 비교 기준으로 삼는다

## 총수가 안 움직이면 거기서 멈추지 말고 실패를 분해하라

plan007 에서 근거 예산을 고쳤는데 회수 실패가 12에서 12로 총수가 같았다. 남은 실패 19건을 갈랐다.

| 갈래 | 건수 |
| --- | ---: |
| 부모 업무는 근거에 왔는데 그 근거만 빠졌다 | 12 |
| 부모 업무에 도달하지 못했다 | 7 |

앞쪽 8회의 Cypher 를 직접 열어 원인을 찾았다. **`LIMIT 50` 이라고 짐작했으나 아니었다** — 지목된
업무 중 하나만 댓글을 확장하고 있었다. 프롬프트를 고치자 실패가 (12, 12) 에서 (7, 9) 로 떨어졌다.

- **하지 말 것**: 총수가 같으면 "효과 없음" 으로 결론하기
- **대신 할 것**: 실패를 원인별로 갈라 세고, 의심되는 회차의 **생성된 Cypher 를 직접 읽는다**
- **개선이 의도한 기제 때문인지 확인하라.** `AGW-A02` 가 4→0 이 됐을 때 3회 전부 프롬프트에 넣은
  패턴(`WHERE t.number IN [...]`)을 그대로 쓴 것을 Cypher 로 확인했다

## 부분 재측정으로 전체를 단정하지 마라

인수 리포트의 "human 89.4%" 는 개선 루프 후 3문항만 재측정하고 나머지는 이전 값을 유지해 계산한 값이었다.

## 기준선에 없는 데이터를 비교 대상으로 요구하지 마라

plan006 phase-03 이 "질의 소요 시간 전후 비교" 를 요구했는데 **기준선에 지연 필드가 0건**이었다.
지연을 담은 원시 실행 결과는 커밋 대상이 아니라 남아 있지 않았다.

- **대신 할 것**: 비교를 요구하기 전에 **그 값이 기준선에 있는지 확인**한다. 없으면 절대값만 기록하고
  "비교 불가" 와 그 이유를 리포트에 명시한다. 그 값이 다음 비교의 기준선이 된다

## 측정용 API 를 `pnpm` 으로 백그라운드에 띄우지 마라

`pnpm` 이 자식 프로세스 출력을 파이프로 중계하므로, 띄운 셸이 끝나면 파이프가 끊기고 API 가 다음
로그 쓰기에서 `EPIPE` 로 죽는다.

실측 — 36회 측정 중 **35회가 `fetch failed`** 로 날아갔다. 첫 회차만 성공했고 로그 끝에
`Error: write EPIPE` 가 남아 있었다. **Nest 는 정상 기동했으므로 기동 실패로 보이지 않는다.**

- **대신 할 것**: `node dist/main.js` 를 직접 띄운다. `.env` 를 셸에 먼저 적재해야 설정 검증을 통과한다

  ```bash
  # cwd: 저장소 루트
  cd apps/api && set -a && . ../../.env && set +a && nohup node dist/main.js >| /tmp/api.log 2>&1 &
  ```

- **API 기동과 측정을 같은 명령에 묶지 마라.** 기동 → 준비 확인 → 측정을 각각 나눈 호출로 한다

## 한글 길이를 잴 때 escape 여부를 구분하라

JS `JSON.stringify` 는 한글을 그대로 두고 파이썬 `json.dumps` 는 기본이 `\uXXXX` 다.
같은 근거가 34,615자와 57,466자로 갈린다. 이 차이를 놓쳐 프롬프트 절단 심각도를 한 번 잘못 보고했다.

## 인프라 전제

- **운영 Neo4j(7687)는 이 저장소의 로컬 Docker 컨테이너다** (`devloop-v2-neo4j-1`).
  `lsof` 에 `ssh` 로 보이는 것은 **colima** 가 Docker 를 Lima VM 으로 돌리며 포트를 포워딩하기
  때문이고 원격 서버 터널이 아니다. 샌드박스에서 접근이 막히는 것은 맞다 — codex 를 샌드박스로
  돌리면 "Neo4j 가 안 뜬다" 고 보고한다
- **테스트용 7688 은 다른 프로젝트 컨테이너(`fos-graphrag-neo4j-1`)가 점유한다.**
  그래서 `pnpm --filter api test:e2e` 는 컨테이너 기동 단계에서 막힌다. 그 인스턴스는 이 저장소
  자격증명을 거부하므로 데이터가 지워질 위험은 없다 — 다만 우연히 막힌 것이다
- **`--data-dir` 에는 절대 경로를 써라.** 상대 경로는 pipeline 패키지 기준으로 풀려 파일을 못 찾는다

## 화면 검증

- **playwright 의 `fill()` 은 React onChange 를 우회한다.** 입력값이 state 에 반영되지 않아
  **이전 질문이 재전송**된다. 질의 화면을 검증할 때는 `slowly: true`(= `pressSequentially`)를 쓴다
- **근거 그래프 캔버스는 좌상단만 보지 마라.** 545×2437 처럼 세로로 길고 노드는 중앙에 배치된다.
  좌상단 400×400 을 샘플링하면 정상 상태에서도 픽셀이 0 으로 나온다. 전체를 격자로 훑는다
  (8~10px 간격). 픽셀이 0 이면 먼저 **근거 건수가 0 인지** 확인한다
