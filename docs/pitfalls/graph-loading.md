# 함정 — 그래프 적재

**`sync-neo4j`·`reset-neo4j`·`apply-schema` 를 돌리기 전에 읽는다.**

## 적재기는 MERGE 전용이라 재적재로 노드가 줄지 않는다

`sync-neo4j` 에 삭제 경로가 없다. 정규화를 고쳐 노드가 합쳐지게 만들어도 그냥 재적재하면
**기존 파편 노드가 그대로 남는다.**

- **노드를 줄이려면** `reset-neo4j --force` → `pnpm apply-schema` → 적재 순서로 초기화한다.
  `reset-neo4j` 는 `NEO4J_URI` 를 필수로 요구하고, 운영 포트(`7687`)는 `--allow-production` 도 필요하다
- **속성만 바꾸는 변경은 초기화가 필요 없다.** 적재기가 `SET n += row.properties` 로 덮어쓴다
  (`sync.ts`). 되돌릴 수 없는 작업을 이유 없이 하지 않는다
- 데이터는 `apps/pipeline/data/graph/tc-ocr/*.jsonl` 에 있으므로 초기화 후 재적재로 완전 복원된다.
  LLM 캐시(`data/cache/`)가 있어 추출 재실행은 불필요하다

## 되돌릴 수 없는 적재는 예측을 먼저 세우고 실행하라

2026-07-30 별칭 병합 재적재에서 실측이 사전 예측과 모든 유형에서 정확히 일치했다. 방법이다.

- `resolve-graph` 산출 파일에서 관계를 `(type, startKey, endKey)` 로 묶어 **고유 개수**를 센다.
  적재기가 MERGE 하므로 레코드 수(13,078)가 아니라 이 값(13,002)이 적재 후 건수다
- **라벨·관계 유형별 표를 전후로 만든다.** 총계만 보면 어느 유형이 왜 줄었는지 못 읽는다
- 예측과 실측이 어긋나면 그 자리에서 원인을 찾는다. 사후에 숫자만 보고 해석하면 늦다

## 관계 1건은 원천 결함으로 항상 건너뛴다

`Decision:127-2 -[:EVIDENCED_BY]-> Comment:3337602802353084377` 의 끝점 Comment 가 원천에 없다.
LLM 이 19자리 댓글 id 한 자리를 틀렸다 (실제는 `3327602802353084377`).

- 적재기 가드(`resolve/endpoint.ts`)가 잡아 관계를 버리므로 피해는 없다
- **근접 교정을 하지 마라** — 한 자리 차이를 자동으로 고치면 우연히 존재하는 다른 댓글에 붙어
  가짜 엣지가 된다. 관계 1건 잃는 쪽이 낫다

## 관계를 새로 추가하면 질의 쪽이 그것을 아는지 확인하라

추출기는 문서와 개념을 잇는 관계를 깊이에 따라 나눈다.

| 관계 | 의미 | 건수 |
| --- | --- | --- |
| `MENTIONS` | 본문에서 스쳐 언급된 개념 | 4,149 |
| `DOCUMENTS` | 그 위키가 설명·문서화하는 주제 개념 | 235 |

`DOCUMENTS` 가 더 강한 관계다. `[:MENTIONS]` 만 매치하면 **정답에 가까운 문서일수록 빠진다.**
질의 프롬프트에 두 관계를 함께 매치하라는 지시를 넣어 A-07 이 통과로 바뀌었다.

- **온톨로지에 정의만 하고 프롬프트에 알리지 않으면 조용히 도달 불가가 된다**

## 오탐 제거가 지표를 낮출 수 있다

`REFERENCES` 786건 중 458건이 오탐이었다. 패턴이 `단어/숫자` 를 전부 업무 참조로 봤다.

| 유형 | 건수 |
| --- | --- |
| 자기참조 (본문이 자기 번호를 언급) | 202 |
| URL·경로 조각 (`.../pull/52`, `./images/16.jpg`) | 225 |
| 타 프로젝트 참조가 같은 번호의 tc-ocr 업무로 둔갑 | 33 |

마지막 유형은 Task 노드 키가 번호뿐이라 생겼다 — `CV-OCR/78` 이 tc-ocr 의 78번을 가리켰다.

- 정리 후 328건이고 전부 `tc-ocr` 내부 참조다
- **숫자가 나빠졌다고 회귀로 단정하지 마라.** A-14 는 가짜 엣지를 타고 도달해 통과하던 문항이라
  실패로 바뀌었다. 없앤 엣지가 진짜였는지 확인한다

## 텍스트 규칙은 도착하는 값을 기준으로 정하라

`textContent`(`raw-reader.ts`)가 `\s+` 를 공백 하나로 병합해 **개행을 지운다.**
원천 JSON 은 여러 줄이지만 저장 직전 함수에 도착하는 값은 한 줄이다.

- 원천 파일을 기준으로 "두 줄 고정 형태" 규칙을 썼더니 **0건 매칭**됐다
- **대신 할 것**: 규칙을 쓸 함수에 **실제로 도착하는 값**을 먼저 찍어 본다
- 저장용 값에만 가공을 적용하고 **참조 추출 입력은 원문 그대로 넘긴다.** 위쪽에서 가공하면
  `REFERENCES` 328건이 조용히 바뀐다

## 환경변수 부재가 조용히 다른 모델로 돌게 만들었다

`.env` 에 `QUERY_LLM_MODEL` 이 있었지만 **API 가 그 파일을 읽지 않았다.** dotenv 없이
`node dist/main.js` 로 뜨기 때문이다. `llm-cli.ts` 가 모델이 없으면 `-m` 를 아예 붙이지 않아
`codex exec` 가 자기 기본 모델로 실행됐다.

- 지금은 `@nestjs/config` 에 zod 검증을 물려 **필수 값이 없으면 기동이 실패**한다 (ADR 0003)
- 다른 값들은 코드 기본값이 `.env` 와 우연히 같아 드러나지 않았다. **우연한 일치가 가장 위험하다**
- e2e 도 같은 함정이었다 — `AppModule` 을 최상단에서 `require` 하면 설정이 `before()` 보다 먼저 굳어
  테스트가 운영 DB(7687)에 붙는다. `test/helpers/e2e-env.js` 를 `node --require` 로 선주입해 막았다

## 사전과 판단

- Concept 정규화는 2단계다 — `normalizeText`(대소문자·공백), `normalizeConceptKey`(구두점).
  2단계는 별칭 경로에만 적용된다. 1단계는 참조 해석에도 쓰이므로 함부로 바꾸면 관계가 깨진다
- 사전 중복 항목이 있으면 강화 키가 충돌해 적재가 예외로 멈춘다. override 표로 덮지 말고
  **사전을 통합**하는 것이 옳다
- **토큰 일치만으로 자동 병합하면 안 된다.** `gateway api`(쿠버네티스 표준)와 `api gateway`(OCR 앞단)는
  토큰 집합이 같지만 별개 개체다. 부분포함 탐지는 1,247쌍이 나오지만 대부분 오탐이다
