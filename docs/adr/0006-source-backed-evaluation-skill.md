# 0006 — 대표 업무 흐름을 원천 근거 기반 평가 스킬로 반복 측정한다

**상태**: 채택

## 결정

지식그래프 검색 품질은 모든 업무에서 자동 생성한 질문이 아니라,
관계가 짙고 원천 기록이 잘 정리된 대표 업무 흐름으로 반복 측정한다.
첫 기준 흐름은 tc-ocr의 API Gateway 제거 업무로 둔다.

정답은 원천 업무·댓글·위키에서 먼저 만들고,
원천·그래프·검색·답변의 네 경계를 분리해 판정한다.
원천에 직접 근거가 없는 관계 질문은 실패 분모에서 빼고,
근거 없는 인과를 만들지 않는지 확인하는 음성 대조로 사용한다.

평가는 별도 애플리케이션이 아니라 저장소 전용 `kg-eval` 스킬이 소유한다.
같은 문항을 최소 3회 직렬 실행하고,
결정적 검사와 서로 독립된 두 의미 판정을 함께 기록한다.
반복 결과가 흔들리거나 의미 판정이 갈리면 평균내지 않고 `REVIEW`로 보낸다.

## 맥락

기존 질문 은행과 채점 기준은 있었지만 실행이 수동이었다.
한 번 실행한 결과는 앵커 추출과 Cypher 생성의 변동 때문에 회귀 기준으로 쓸 수 없었고,
답이 없는 원천 문항까지 검색 실패로 세어 원인을 잘못 분류했다.

그래프에서 정답을 다시 만들면 추출되지 않은 사실을 발견할 수 없다.
검색 결과만 채점하면 원천 부재, 그래프 적재 누락, 검색 실패, 답변 합성 실패도 구분되지 않는다.
AI 에이전트용 컨텍스트 제공자의 품질을 올리려면 최종 답변 점수보다 어느 경계가 끊겼는지 알아야 한다.

## 기각한 대안

**490개 업무 전체에서 문항을 자동 생성한다.**
넓은 범위는 얻지만 원천을 읽고 확정하지 않은 자동 정답이 평가 대상과 같은 모델의 추론을 답으로 굳힌다.
먼저 소수의 깊은 흐름으로 실패 분류가 실제 개선에 쓰이는지 검증한다.

**평가 전용 애플리케이션과 API를 추가한다.**
평가는 제품 실행 경로가 아니라 개발 품질 게이트다.
현재 질의 API로 필요한 응답을 얻을 수 있어 별도 배포 단위와 의존성을 만들 이유가 없다.
반복 절차와 결정적 검사는 스킬의 번들 스크립트로 충분하다.

**사람형·AI 에이전트형 평가를 별도 스킬로 유지한다.**
질문 표현은 다르지만 실행, 반복, 실패 경계, 리포트 계약은 같다.
분리하면 같은 절차와 판정 규칙이 다시 어긋난다.
하나의 스킬 안에서 `audience`로 구분한다.

**두 의미 판정의 점수를 평균낸다.**
판정 차이는 문항이나 기준의 모호성을 드러내는 신호다.
평균은 그 신호를 숨기므로 사람 검토 대상으로 남긴다.

## 결과

평가 결과는 질문별 성공률만이 아니라 실패 경계와 반복 안정성을 제공한다.
원천이 없는 관계를 모른다고 답하는 능력도 품질로 측정한다.

원시 응답은 조직 내부 정보가 들어갈 수 있어 저장소에 커밋하지 않는다.
커밋에는 실행 조건, 축별 판정, 안정성, 회귀 비교에 필요한 요약만 남긴다.

`kg-model-bench`는 모델 비교를 계속 소유하지만,
검색 품질 판정은 `kg-eval` 결과를 재사용한다.
