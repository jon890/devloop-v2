# ADR 0002 — LLM 을 구독 CLI 로만 호출한다

- 상태: 채택
- 결정일: 2026-07-22 (깊이 인터뷰 R5)
- 기록일: 2026-07-29

## 맥락

추출과 질의응답 양쪽에서 LLM 을 부른다. 규모를 계산하면 이렇다.

- 추출 — 문서 537건에 문서당 1회. 프롬프트를 고치면 캐시가 무효화돼 전량 재호출
- 질의 — 질문 1건당 3~5회. 34문항 3회 측정이면 약 360회

학습 목적의 개인 프로젝트인데 반복 측정이 본질이라 호출 횟수가 계속 늘어난다.

## 결정

**구독 계정 CLI 만 쓴다. 종량제 API 는 금지한다.**

- 1순위 상주 `codex app-server` (OpenAI Codex 계정)
- 허용 `claude -p` (Claude Code 헤드리스)
- CLI 어댑터 인터페이스로 추상화해 교체 가능하게 한다

1순위 수단이 `codex exec` 에서 상주 `codex app-server` 로 바뀌었다 ([ADR 0008](0008-persistent-llm-transport.md)).
같은 구독 계정이고 `codex` CLI 의 공식 실행 모드라 이 결정의 제약 안에 있다.

## 이유

- **관리 대상이 비용이 아니라 시간이 된다.** 구독은 정액이므로 호출 횟수를 아끼는 대신
  전체 처리 시간을 관리 지표로 삼을 수 있다
- 반복 측정이 품질 판정의 전제다. 1회 측정으로 판정할 수 없다는 것이
  실측으로 확인됐으므로(변동 문항 비율 7~29%) 호출을 아끼는 설계는 목적과 충돌한다

## 결과

**좋은 쪽**

- 3회 반복 측정을 비용 걱정 없이 돌린다
- 어댑터 추상화로 모델·제공자를 바꿔 벤치마크할 수 있다

**대가**

- **한 서버에 호출이 몰린다.** 상주 전송으로 옮긴 뒤에는 프로세스 경쟁이 아니라 서버 하나가
  단일 실패 지점이 된다 (ADR 0008 의 대가 절). 동시 턴은 `threadId`·`turnId` 로 갈라낸다.
  측정 중 같은 API 로 다른 질의를 하면 결과가 불안정해지는 것은 **옛 CLI 구조에서 실측한 것이고
  상주 전송에서는 다시 재지 않았다** — 경고는 유지하되 근거가 갱신되지 않았음을 밝힌다
- 구독 사용량 한도가 실질 제약이 된다. 측정 도중 한도에 걸리면 측정을 다시 해야 한다
- **모델 지정이 어댑터 인자에 의존한다.** 모델이 지정되지 않으면 CLI 기본 모델로 조용히 실행된다.
  이 함정이 실제 사고로 이어져 ADR 0003 을 낳았다

## 대안으로 남겨 둔 것

호출을 줄이는 방법들이다. 지금은 채택하지 않았지만 한도에 걸리면 검토한다.

| 방법 | 절감 | 손실 |
| --- | --- | --- |
| 수동 판정 문항을 반복 측정에서 제외 | 약 23% | 없다. 이미 자동 판정에서 빠져 있다 |
| 답변 합성 생략 모드 | 25~30% | 무환각 축을 판정할 수 없다. 최종 회차만 켜면 해소된다 |
| 단계별 추론 강도 분리 | 미측정 | 품질 영향을 측정으로 확인해야 한다 |
| 질의 응답 캐시 | 큼 | **측정에 쓸 수 없다.** 변동성이 0으로 보여 반복 측정의 의미가 사라진다 |

## 관련

- `docs/flow.md` — 질의 1건당 호출 지점
- ADR 0003 — 모델 지정이 누락됐을 때의 사고
- [ADR 0008](0008-persistent-llm-transport.md) — 1순위 수단을 상주 `app-server` 로 옮긴 결정.
  이 결정을 대체하지 않고 그 제약 안에 있다
