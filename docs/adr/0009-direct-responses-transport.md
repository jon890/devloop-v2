# ADR 0009 — LLM 호출을 Responses 엔드포인트로 직접 보낸다

- 상태: 채택
- 결정일: 2026-08-06
- 기록일: 2026-08-06

[ADR 0008](0008-persistent-llm-transport.md) 을 대체하지 않고 **기본 전송만 바꾼다.**
상주 `app-server` 어댑터는 되돌릴 길로 남고 0008 의 실측과 판단은 그대로 유효하다.

## 맥락

0008 이 프로세스 기동 8초를 없애 질의 지연을 59.7초에서 41.6\~44.2초로 줄였다.
그 뒤 남은 지연을 분해하니 **모델이 답하는 시간보다 실려 가는 맥락이 크다.**

`app-server` 는 **에이전트 턴**을 돌린다. Codex 시스템 프롬프트, 도구 정의, 지시 파일이
호출마다 함께 간다. 우리 질의 엔진은 도구를 쓰지 않고 프롬프트 하나에 JSON 하나를 받는다.
그 비계 전부가 우리 용도에는 낭비다.

## 결정

**`https://chatgpt.com/backend-api/codex/responses` 로 직접 보낸다.**

- 인증은 `~/.codex/auth.json` 의 ChatGPT 계정 토큰을 쓴다 (`access_token`·`account_id`)
- **토큰 갱신을 우리가 구현하지 않는다.** 호출할 때마다 `auth.json` 을 읽어 `codex` 가 갱신한
  값을 따라가고, 401 이면 즉시 실패시키며 `codex` 를 한 번 실행하라는 메시지를 담는다
- 응답 형식은 `text.format.json_schema` 로 넘긴다 (`strict: true`)
- 추론 강도는 `reasoning.effort` 로 넘긴다
- 전송은 설정 스위치로 고른다. 기본은 직접 호출이고 상주 `app-server` 를 남긴다
- `claude -p` 어댑터도 그대로 남는다

**`ADR 0002` 를 어기지 않는다.** 같은 구독 계정이고 종량제 과금이 아니다.
`OPENAI_API_KEY` 는 `auth.json` 에서 `null` 이며 종량제 경로(`api.openai.com`)를 쓰지 않는다.

## 이유

같은 프롬프트(16KB)·같은 스키마를 두 전송으로 **번갈아** 6라운드씩 돌렸다.

| 전송 | 중위 | 평균 | 범위 | 평균 답변 | 문자당 |
| --- | ---: | ---: | --- | ---: | ---: |
| `app-server` 상주 | 15.7초 | 15.3초 | 13.8\~17.0초 | 554자 | 27.6ms |
| Responses 직접 호출 | 11.1초 | 9.7초 | 7.5\~11.7초 | 712자 | 13.6ms |

**구간이 겹치지 않는다** (A 최소 13.8초 > B 최대 11.7초).
직접 호출은 답변을 더 길게 쓰면서도 더 빠르다 — 문자당으로는 두 배다.

질의당 LLM 호출이 3\~5회이므로 **17\~28초 여지**다.

번갈아 돌린 이유가 있다. 한쪽을 몰아 돌렸을 때 그 시간대의 경쟁이 그 팔에만 실려
**반대 결론이 나온 것을 실측으로 겪었다.** 전송 비교는 반드시 교차로 잰다.

## 함께 못 박는 것 — 추론 강도

`LLM_REASONING_EFFORT` 가 설정되어 있지 않아 지금은 강도를 넘기지 않는다.
그러면 **전송마다 자기 기본값을 쓴다** — `app-server` 는 `~/.codex/config.toml` 을 보고
직접 호출은 서버 기본값을 쓴다.

그 상태로 전송을 바꾸면 지연 변화가 전송 덕인지 강도 덕인지 가를 수 없다.
모델을 지정하지 않아 조용히 기본 모델로 돌던 사고가 [ADR 0003](0003-fail-fast-config.md) 을 낳았고
이건 같은 성격이다. **그래서 강도를 설정으로 명시하고 두 전송에 같은 값을 싣는다.**

엔드포인트가 값을 검증한다. 지원 값은 `none`·`minimal`·`low`·`medium`·`high`·`xhigh`·`max` 이고
엉뚱한 값에 400 과 지원 목록을 돌려준다.

## 기각한 대안

| 대안 | 기각 사유 |
| --- | --- |
| `app-server` 를 계속 기본으로 둔다 | 질의당 17\~28초를 포기한다 |
| `api.openai.com/v1/responses` 를 쓴다 | 종량제 API 다. `ADR 0002` 가 금지한다 |
| 토큰 갱신을 직접 구현한다 | 자격증명을 다루는 코드가 늘어난다. `codex` 가 이미 한다 |
| `app-server` 어댑터를 지운다 | 문서화되지 않은 엔드포인트가 바뀌면 되돌릴 길이 없어진다 |
| microsoft/graphrag 로 갈아탄다 | `GRAPHRAG_API_KEY` 로 종량제 API 를 요구한다.<br>고정 온톨로지·Cypher 재현 평가·Dooray 수집기를 버리게 되고,<br>PRD 가 못 박은 학습 목적과도 어긋난다 |

## 결과

**좋은 쪽**

- 질의 지연이 더 내려간다. 호출당 15.3초에서 9.7초 수준이다
- 측정 반복이 다시 빨라진다
- 보내는 것을 우리가 온전히 통제한다 — 에이전트 프롬프트가 바뀌어도 우리 결과가 흔들리지 않는다

**대가**

- **문서화되지 않은 내부 엔드포인트다.** 공개 API 계약이 아니라 예고 없이 바뀔 수 있다.
  그래서 상주 어댑터를 남긴다
- **토큰 만료가 새 실패 모드다.** `access_token` 수명은 240시간이고 `codex` 가 갱신한다.
  오래 `codex` 를 안 쓰면 401 이 난다
- **에이전트 프롬프트가 빠져 답변 문체가 바뀐다.** 실측에서 답변이 554자에서 712자로 길어졌다.
  지연만 보지 말고 근거 회수와 답변 길이를 함께 봐야 한다
- **파이프라인 추론 강도는 미지정으로 남는다.** 명시하면 `gpt-5.5@default` 캐시 537건이 전부
  빗나간다. 재추출할 때 강도를 정하고 캐시 무효화를 감수해야 한다
- 스트림 파싱을 우리가 갖는다. SSE 이벤트 형식이 바뀌면 여기서 깨진다

## 후속으로 남긴 것

**호출별 추론 강도 분리.** 지금은 모든 호출이 한 값을 쓴다.
앵커 용어 추출에 `high` 가 필요한지는 확인되지 않았고, 실측에서 `low` 와 `high` 가
5.8초 대 9.8초였다 (각 1회라 크기는 근거가 약하다). 별개 지레라 이 결정에 섞지 않는다.

## 관련

- ADR 0002 — 구독 계정 제약. 이 결정이 그 안에 있다
- ADR 0003 — 값 미지정으로 조용히 기본값을 쓰던 사고
- ADR 0008 — 상주 전송. 되돌릴 길로 남는다
