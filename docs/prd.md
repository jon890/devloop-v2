## 문제

업무 관리 도구(Dooray)에 쌓인 업무·위키는 검색은 되지만 **관계를 따라갈 수 없다.**

실제로 답하기 어려운 질문들이다.

- "이 결정을 왜 했나" — 결정과 그 근거 댓글, 결정이 내려진 업무가 흩어져 있다
- "이 장애와 이어진 업무는 무엇인가" — 인과 사슬이 본문 안에만 있다
- "이 개념을 다루는 문서는 어디인가" — 제목 검색으로는 표기가 다르면 못 찾는다

키워드 검색과 벡터 유사도 검색은 **문서 하나를 찾아 주지만 문서 사이의 연결을 주지 않는다.**

## 목표

업무·위키를 고정 온톨로지 기반 지식그래프로 만들고, 자연어 질문에 **근거 서브그래프와 함께** 답한다.

세 가지를 갖춘다.

- **관계형 질문 응답** — 다단계 관계를 따라가는 질문에 답한다
- **근거 추적** — 답변의 모든 주장이 그래프의 어느 노드·관계에서 왔는지 보인다
- **재실행성** — 수집부터 적재까지 명령으로 다시 돌릴 수 있다

기저 동기는 **GraphRAG·온톨로지·그래프 DB 기술 학습**이다. 제품화가 아니다.

## 사용자와 가치

한 명의 개발자가 쓰는 로컬 도구다.

| 상황 | 지금 | 이 도구로 |
| --- | --- | --- |
| 과거 결정의 배경을 찾을 때 | 업무를 하나씩 열어 댓글을 읽는다 | 결정·근거·관련 업무를 한 번에 받는다 |
| 장애 원인 이력을 볼 때 | 검색어를 바꿔 가며 반복 검색한다 | 인과로 이어진 업무 사슬을 받는다 |
| 개념 관련 문서를 찾을 때 | 제목 표기를 추측한다 | 표기가 달라도 개념 노드로 도달한다 |

## 범위

### 포함

- 한 프로젝트의 업무·위키 전량 수집과 그래프 적재
- 고정 온톨로지 — 노드 7종, 관계 15종
- 자연어 질의응답 REST API 와 근거 서브그래프 시각화 UI
- 축별 독립 품질 판정 체계 (`docs/EVAL-RUBRIC.md`)
- `--project` 파라미터로 다른 프로젝트 색인
- 사람이 확인해 승인한 Concept 동일성 판단을 관계형 저장소에 남기고 승인 화면으로 다룬다

### 제외

| 제외 항목 | 이유 |
| --- | --- |
| 증분 동기화 | 전량 재실행으로 갈음한다. 데이터 규모가 작다 |
| 여러 프로젝트를 한 그래프에 통합 | 프로젝트별로 따로 색인한다 |
| Milestone 축 모델링 | 대상 팀이 마일스톤을 거의 쓰지 않는다 |
| 온톨로지 스키마 자동 진화 | 고정 스키마로 시작한다. 이후 과제다 |
| 멀티유저 서비스화 | 로컬 개인 도구다 |
| 벡터 유사도 검색 대체 | 관계형 질문·히스토리 추적에 집중한다. 서로 대체가 아니라 보완이다 |

## 확정된 설계 판단

깊이 인터뷰에서 가정을 하나씩 반문해 확정했다.

| 가정 | 검증 방식 | 결론 |
| --- | --- | --- |
| 그래프가 벡터 검색보다 나은가 | 벡터 검색과 비교 반문 | 관계형 질문·결정 히스토리·근거 시각화가 그래프 고유 가치다. 우열이 아니라 영역이 다르다 |
| 전체 데이터가 필요한가 | 최소 조각으로 되는지 확인 | 537건 규모라 전량 1회 적재로 단순화한다 |
| LLM 을 종량제로 쓸 것인가 | 비용 우려 | 구독 CLI 경유로 추가 과금을 피한다. 관리 대상은 비용이 아니라 **시간**이다 |
| 온톨로지를 자동 생성할 것인가 | 3안 비교 | 고정 스키마로 간다. 자동 진화는 이후 과제다 |

## 성공 기준

판정은 `docs/EVAL-RUBRIC.md` 가 단일 소스다. 통과선과 채점표는 그 문서만 갖는다.

- 대상 업무·위키 전량이 적재되고 라벨·관계별 통계가 출력된다
- 질의응답이 축별 통과선을 넘는다 — 앵커 해석·근거 재현율·무환각·그래프 정합
- 질문하면 답변과 근거 서브그래프가 함께 나오고 노드 클릭으로 이웃을 탐색할 수 있다
- 파이프라인이 명령으로 재실행된다
- 추출용·질의용 기본 모델이 품질·시간 근거와 함께 결정돼 있다

### 성공 기준을 다룰 때의 원칙

**1회 측정으로 판정하지 않는다.** LLM 이 만드는 앵커 용어와 Cypher 가 실행마다 바뀌어
측정 조건에 따라 변동 문항 비율이 7~29% 로 나왔다. 최소 3회 반복해 전회 일치를 확인하고,
변동 문항은 개선도 회귀도 아닌 **판정 불가**로 분류한다.

**점수를 합산하지 않는다.** 축을 합치면 답을 못 찾은 문항도 무환각 만점을 받아 하한이 떠받쳐진다.
실패가 숫자에 묻혀 원인을 읽을 수 없었다. 그래서 축별 독립 판정으로 바꿨다.

### 품질을 올리는 방법은 다른 프로젝트로 반복하는 것이다

한 프로젝트만 보면 그 프로젝트에 맞춘 규칙이 품질처럼 보인다.

- 다른 프로젝트를 `--project` 로 색인하고 사전을 새로 시드한다
- 평가 스킬의 gold 부트스트랩으로 그 프로젝트의 질문 은행을 만들어 **같은 판정 기준으로** 채점한다
- 한 프로젝트에만 맞는 규칙이 드러나면 공통 코어로 일반화한다
